# 健身教练

## 使用

1. 打开「健身」→「身体档案」，填写真实数据、目标、限制、训练日与时间。
2. 打开「我的器材」，添加健身房中具体的器材（不要把不同器材混用同一个档案）。选择单位、重量含义与最小档位。第一版提供推胸、下拉、划船、推肩、腿举、腿弯举、徒手深蹲、死虫式。
3. 右上角「模型接口」填写兼容 OpenAI Chat Completions 协议的 HTTPS 接口地址（如 `https://.../v1`）、模型名称（默认 `glm-5.3-flash`，可按需修改）和 API Key。密钥存 Keychain，不嵌入源码或安装包，不参与 JSON 备份。
4. 有以前的训练时，先到「训练历史」补记日期、动作、目标和实际完成情况。
5. 在健身页选日期与恢复情况，点「生成训练计划」。休息日或有疼痛时可直接生成本地恢复安排，不调用模型。
6. 训练后逐组填写实际重量、次数并勾选完成，选择体感与疼痛反馈后保存。未完成的组不要勾选。

## 记忆与计划

- 新人最多每动作 3 组；疲劳时最多 2 组。计划计入 5 分钟热身、组间休息和 5 分钟放松。
- 前一天练过的肌群和当前酸痛肌群会被排除；疼痛反馈在近期额外避让。疼痛不能仅靠时间判断恢复，持续不适时暂停训练。
- 近 30 天没有该器材可靠记录时，不猜重量，先轻重量试做。lb/kg、单只/总重、器材实例分别对待。
- 连续两次不同日期、同重量完成目标且轻松无痛，才显示试加最小档位的可选按钮；超过当前重量 10% 的档位不自动建议。
- 已验证重量默认继续沿用，吃力或未完成目标则减量。实际新反馈使尚未完成的后续计划失效，需要重新生成。
- 生成期间档案被修改、模型输出异常、超时或取消，都不会覆盖原计划。
- 这是主动生成的每日计划，不依赖 iOS 在后台准点联网。已保存的计划与反馈可离线使用。

## 数据与网络

SwiftData 使用独立的 `Fitness` 本地库，记录身体档案、器材、计划与实际训练。原计划、支出、喝水数据保持原存储方式。

「设置」中的 JSON 备份增加可选 `fitness` 字段，兼容不包含该字段的老备份。导入合并器材/计划/训练标识，已存在记录优先保留；身体档案按备份覆盖。密钥和接口配置不随备份迁移。

仅向模型发送必要的身体信息、可用器材、恢复状态和近期训练摘要；不会发送支出或喝水数据。远程网关要求使用 HTTPS；仅 `localhost` / `127.0.0.1` 本地调试允许 HTTP（明文传输）。

BMI 为体重/身高²，体脂用 RFM 的身高与腰围公式估算，仅适用成年人的粗略趋势参考，不作为医学测量。

## 构建与验证

Xcode 工程使用 `project.yml` 维护，可运行 `xcodegen generate`。使用完整 Xcode 的 iOS 26 或更高 SDK。

```sh
# 在本目录执行
xcodegen generate
xcodebuild -project 'Plan Manager.xcodeproj' -scheme 'Plan Manager' -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build-for-testing
# 在有完整模拟器环境时运行 FitnessTests 与 FitnessUITests
swift test --scratch-path /tmp/plan-manager-fitness-core-tests
```

Swift Package 编译与 App 相同的核心源码，用于没有完整模拟器时的规则和存储测试。可选真实接口测试读取 `/tmp/plan-manager-fitness-live-key`（本地权限应为 600）；文件不存在时跳过，测试完必须删除。不要把密钥放进源码、测试日志或仓库。

## 小精灵下线

当前仓库已完整移除 Go 后端、Vue 管理后台、Docker、宠物模块及相关资源。App 不需要登录或部署后端，直接使用本地数据和配置的 LLM 接口。清理源码没有连接服务器、删除数据库表或删除 Docker 数据卷。
